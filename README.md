# О!дин запрос — AI-агент, который собирает поездку целиком

Трек Островка: одно сообщение пользователя → направление, отель, перелёт, трансфер → корзина с проверкой стыковок → (имитация) оплаты.

Фишка: варианты показываются карточками со свайпом, как в Тиндере. Направления — с ИИ-видео, отели и рейсы — с объяснением «почему / чем пожертвовали / риски». Дизлайк с причиной («дорого», «далеко лететь», «хочу город») меняет ровно этот параметр и пересобирает варианты.

> Сейчас вместо LLM работает **агент на правилах**. Весь сценарий проходит без модели, а LLM подключается в одном месте (см. «Куда подключать LLM»).

## Запуск

```bash
# инфраструктура (Docker): Postgres 16 на порту 5544, Redis на 6380
docker compose up -d

# бэкенд (Python 3.10+); таблицы создаются сами при старте
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --reload --port 8765

# фронт (в другом терминале)
cd frontend
npm install
npm run dev          # http://localhost:5199, /api и /videos проксируются на :8765
```

Для демо одним сервером: `npm run build` во `frontend/`, после чего бэкенд сам раздаёт собранный фронт на `http://localhost:8765`. Ту же ссылку (через ngrok или деплой) можно открыть как Telegram Mini App: вход идёт по подписанным данным Telegram (нужен `TELEGRAM_BOT_TOKEN`), сторонний скрипт Telegram не подключается.

Продакшн: `cp .env.example .env`, заполнить секреты, затем `docker compose -f docker-compose.prod.yml --env-file .env up -d --build`. Наружу открыт только Caddy (80/443) с автоматическим TLS; приложение, Postgres и Redis доступны лишь внутри сети compose. Без секретов (`AUTH_SECRET`, `DATA_ENCRYPTION_KEYS`, `CORS_ORIGINS`, `ADMIN_TOKEN`) сервер в продакшне не стартует.

Метрики качества — прогон 30 тестовых запросов:

```bash
cd backend && .venv/bin/python -m eval.run_eval --verbose
```

Последний прогон: 30/30 запросов доведены до оплаты, пересборка «на 2 дня позже» сработала 30/30, ошибок в стыковках 0, в среднем 0,03 уточнения. Пополняйте `backend/eval/queries.json` запросами «как у жюри».

## Видео

Положите ролики в `data/videos/<id>.mp4` (id берутся из `data/cities.json`: `antalya`, `dubai`, `phuket` и т.д.). По желанию рядом — постер `<id>.jpg`. Видео подхватываются без перезапуска; пока файла нет, на карточке показывается градиент с эмодзи. Имя файла для города можно поменять в поле `video` в `cities.json`.

## Архитектура запроса

```
запрос → JWT → лимиты (Redis) → прочитать сессию (короткая транзакция)
       → агент: правила / LLM — БЕЗ открытого соединения с базой
       → сохранить одной транзакцией: UPDATE … WHERE version = прочитанная
           ├─ успех → ответ
           └─ версия устарела (параллельный запрос успел раньше) → перечитать и повторить (до 3 раз), иначе 409
```

- **Оптимистичная блокировка вместо удержания строки.** Пока агент (и LLM) думает, соединение с базой свободно. Проверено: 30 одновременных запросов с «LLM» по 2 секунды при пуле в 2 соединения отработали за 2,1 с. Параллельные изменения одной сессии не теряются: три одновременных дизлайка учтены все, три одновременных «Оплатить» дали одну бронь. При повторе запрос к LLM выполняется ещё раз — это цена конфликта, но конфликты бывают только у одной и той же сессии.
- **Асинхронный сервер.** Ручки, база (`psycopg` async pool) и хуки агента `understand()` / `phrase()` асинхронные. LLM-команде — только async-клиент (например, `ainvoke`): синхронный вызов заблокирует сервер.
- **Лимиты в Redis** (`security/ratelimit.py`), общие для всех экземпляров, Postgres не нагружают. Если Redis недоступен, запросы пропускаются и пишется ошибка в лог (fail-open): падение Redis не кладёт сервис, но и лимиты в это время не действуют — нужен мониторинг.
- **Обслуживание выполняет один экземпляр.** Каждый экземпляр раз в ~5 минут вызывает `run_maintenance()`, но advisory-блокировка и таблица `maintenance_runs` пускают только один запуск в час на весь сервис. Задача: удаление истёкших сессий, удаление контактов в бронях по сроку хранения, шифрование старых строк.

## База данных

Postgres 16 в Docker (`docker-compose.yml`, порт 5544, логин/пароль/база `odin`). Подключение — `DATABASE_URL`, по умолчанию `postgresql://odin:odin@localhost:5544/odin`. Миграции из `backend/app/db/migrations/` применяются сами при старте, каждая один раз (таблица `schema_migrations`). Новая миграция — новый файл со следующим номером, старые файлы не редактируем.

| Таблица | Что хранит |
|---|---|
| `sessions` | состояние поездки (зашифровано, + `state_version`), колода, метрики, `version` для оптимистичной блокировки, срок жизни |
| `messages` | история чата (зашифрована), отдельно от сессии |
| `profiles` | память о пользователе (зашифрована) |
| `bookings` | брони: статус `confirmed` / `changed` / `cancelled`, даты, сумма, снимок корзины, контакты (зашифрованы) |
| `booking_events` | история брони: создание и каждое изменение с суммой доплаты/возврата |
| `consents` | согласия на обработку ПДн: версия политики, время, отпечаток IP |
| `privacy_log` | выгрузки и удаления данных |
| `analytics_events` | обезличенные продуктовые события |
| `maintenance_runs` | когда и с каким результатом выполнялось обслуживание |

- **Срок жизни.** Сессия живёт `SESSION_TTL_DAYS` (30) дней с последнего действия; сообщения удаляются вместе с ней, брони остаются.
- **Версия схемы состояния.** Переименовали поле или сменили тип в `TripState` — увеличьте `STATE_VERSION` в `models.py` и добавьте функцию в `state_migrations.py`; старые сессии мигрируют при чтении. Сессию от более новой версии кода API не трогает (409).

Посмотреть данные: `docker compose exec db psql -U odin -d odin`. Сбросить всё: `docker compose down -v`. Прогон eval работает во временной схеме и удаляет её в конце.

## Безопасность и персональные данные

- **Вход.** `user_id` выдаёт сервер в подписанном JWT: анонимный вход (`POST /api/auth/anonymous`) или вход по `initData` Telegram с проверкой подписи ключом бота (`POST /api/auth/telegram`). Сессии и брони видит только владелец.
- **Лимиты:** обращения к агенту — в минуту, в сутки и общий суточный потолок сервиса (бюджет на LLM); вход — по IP. Длина сообщений и размер запросов ограничены.
- **CORS** — только домены из `CORS_ORIGINS`. **HTTPS:** редирект, HSTS; CSP без сторонних скриптов, `nosniff`, `Referrer-Policy`, `Permissions-Policy`; Telegram может встраивать приложение во фрейм.
- **152-ФЗ:** поездка, переписка, профиль и контакты шифруются в базе (Fernet, ключи в `DATA_ENCRYPTION_KEYS`, ротация — несколько ключей через запятую). Оформление — только с согласием, оно записывается. Политика — `frontend/public/privacy.html` (шаблон: заполнить данные оператора и согласовать с юристом). В интерфейсе есть «Скачать мои данные» (`GET /api/me/export`) и «Удалить мои данные» (`DELETE /api/me`). Контакты в бронях удаляются через `BOOKING_PII_RETENTION_DAYS` после выезда.

## Аналитика

После каждого ответа агента в `analytics_events` пишутся события: начало сессии, показ вариантов, лайки и дизлайки с причинами, изменения плана, корзина готова, бронь оформлена. В событиях нет `user_id`, текста сообщений, контактов и возраста детей. Связь событий с сессией — через отпечаток id сессии, после удаления сессии её не восстановить. Удаление данных пользователя аналитику не затрагивает.

Отчёт: `GET /api/analytics/funnel?days=30` (заголовок `X-Admin-Token`): воронка «начали → увидели варианты → выбрали направление → отель → корзина → оформили», топ причин дизлайков, популярность направлений.

## Климат

Нормы по месяцам — из Open-Meteo (ERA5): дневной максимум воздуха и дни с осадками ≥ 2,5 мм за 2021–2025, температура моря (Marine API) за 2023–2025. Порог 2,5 мм подобран сверкой: при стандартных 1 мм ERA5 завышает число дождливых дней в тропиках в среднем на ~4 дня. Данные заранее скачаны в `data/climate.json`, поэтому демо не зависит от доступности Open-Meteo. Обновить: `cd backend && .venv/bin/python -m scripts.fetch_climate --force` (бесплатный лимит Open-Meteo медленный — около 10 минут). Лицензия CC BY 4.0, ссылка на источник есть в интерфейсе. Для коммерческого использования у Open-Meteo нужна платная подписка.

## Как расширять

- **Новая причина дизлайка** — правило в `DISLIKE_RULES` (`agent/feedback.py`) и кнопка в `*_REASONS` (`agent/cards.py`).
- **Новая команда в чате** («добавь страховку») — регулярка в `nlu.py`, обработка в `agent/intents.py`.
- **Новый этап** (поезд, экскурсии) — функция-показ и условие в списке `STAGES` (`agent/planner.py`), поле в `TripState`, сброс в `trip_ops.clear`.
- **Настоящий источник данных** — заменить генерацию внутри функции поиска в `tools.py`; ранжирование и объяснения останутся.
- **Город** — запись в `data/cities.json`.

После любых изменений прогоните `python -m eval.run_eval`: метрики не должны просесть.

## API

Все ручки, кроме `health`, `privacy`, `catalog` и входа, требуют `Authorization: Bearer <token>`. Ответ на любое событие агента — `AgentReply`:

```jsonc
{
  "text": "…ответ агента…",
  "cards": [Card],                 // текущая колода (направления | отели | перелёты)
  "deck_kind": "destination",
  "quick_replies": ["Хочу подешевле", "…"],
  "steps": [{"tool": "search_hotels", "summary": "7 отелей → можно с питомцем → осталось 2"}],
  "changes": ["Даты: 7–14 ноября → 9–16 ноября", "…"],   // что поменялось при пересборке
  "ui_action": "open_cart" | "open_checkout" | "open_booking" | null,
  "state": StateView               // TripState + корзина, итог, проблемы стыковок, таймлайн
}
```

| Метод | Тело | Что делает |
|---|---|---|
| `POST /api/auth/anonymous` | — | анонимный вход → `{token, user_id, policy_version}` |
| `POST /api/auth/telegram` | `{init_data}` | вход из Telegram Mini App с проверкой подписи |
| `POST /api/session` | — | новая сессия, приветствие (с учётом памяти) |
| `POST /api/chat` | `{session_id, message}` | сообщение пользователя |
| `POST /api/feedback` | `{session_id, card_id, kind, action: like\|dislike, reason?, comment?}` | лайк / дизлайк с причиной |
| `POST /api/action` | `{session_id, type, payload}` | `set_params`, `set_priorities`, `remove_item`, `add_extra`, `reset` |
| `POST /api/checkout` | `{session_id, contact_name, contact_email, consent, policy_version}` | имитация оплаты, бронь, напоминания |
| `GET /api/bookings/{id}` | — | своя бронь со статусом и историей изменений |
| `GET /api/me/export` / `DELETE /api/me` | — | выгрузить / удалить свои данные |
| `GET /api/metrics`, `GET /api/analytics/funnel` | — | метрики и воронка (`X-Admin-Token`) |
| `GET /api/catalog` | — | направления и наличие видео |

## Куда подключать LLM

Весь агент — `RuleAgent` в `agent/rule_agent.py`. У него два хука, их переопределяет `agent/llm_agent.py` (включается так: `AGENT=llm`):

1. `async understand(text, state) -> ParseResult` — разобрать сообщение. Попросите GigaChat вернуть JSON в формате `ParseResult` (`agent/nlu.py`). Если модель ошиблась, откатывайтесь на правила (`super().understand`). Это даст лучшее понимание запросов при той же надёжности сценария.
2. `async phrase(draft, state) -> str` — переписать черновой ответ живым языком, не меняя цифры.

Если нужен полноценный tool-calling агент, функции из `tools.py` уже возвращают отранжированные варианты с объяснениями, их можно обернуть в `@tool` как есть. Состояние держите в `TripState`, а не в истории чата.

## Что честно сказать на демо

- Отели, рейсы, цены — синтетика: генерируются детерминированно, но правдоподобно, с учётом сезона, города и состава.
- Климат — реальные нормы Open-Meteo за последние годы, не прогноз на конкретные даты.
- Видео направлений сгенерированы ИИ (на карточке есть пометка). Отели показываются без сгенерированных картинок.
- Оплата имитируется.
